# Solana Ed25519 curve vectors

This small, locked Rust program generates the committed fixture consumed by
`SolanaEd25519CurveConformanceTests`. It is first-party defensive conformance
testing for Sava's PDA curve-membership predicate; it is not part of the
published library and Gradle does not run Rust or access the network.

The oracle pins the semantic dependency versions used by Agave v4.2.0:

- `solana-pubkey` 4.2.0's host-side `bytes_are_curve_point`, which is the SDK
  predicate used while finding PDAs;
- `solana-curve25519` 4.0.1's `edwards::validate_edwards`, which is the Edwards
  validation backend called by Agave's `SyscallCurvePointValidation`;
- `solana-address` 2.6.1 and `curve25519-dalek` 4.1.3, pinned explicitly so a
  fresh Cargo resolution cannot silently select a newer decompressor.

The generator also pins Agave's Rust 1.96.1 toolchain. The fixture records and
the Java test verifies the generator, manifest, toolchain, and lock hashes; the
lock validation includes each semantic crate's crates.io checksum. Local Git
attributes force LF for every hashed or byte-compared source and fixture.

For every row the generator requires the SDK predicate and Agave runtime
backend to agree before writing either verdict. The fixture therefore checks
the 32-byte predicate shared by host PDA derivation and the runtime backend. It
does not execute an SBF program and does not test syscall ABI translation,
feature activation, or compute metering.

Canonical source is in the
[`anza-xyz/solana-sdk`](https://github.com/anza-xyz/solana-sdk) and
[`anza-xyz/agave`](https://github.com/anza-xyz/agave) repositories; the exact source
and crate commits are recorded in the fixture header. Local clones may live anywhere,
because the generator itself resolves only the locked crates. Regenerate or verify from
this directory with:

```sh
NO_DNA=1 cargo run --locked --release -- --write
NO_DNA=1 cargo run --locked --release -- --check
```

`--check` compares generated bytes with the committed TSV. Any dependency
change must update `Cargo.lock`, regenerate the fixture, and deliberately update
the pinned metadata asserted by the Java test.
