# Solana legacy/v0 non-lookup message vectors

This locked Rust program generates the committed legacy-message fixture consumed by
`LegacyMessageConformanceTests`. It is first-party defensive conformance testing for
Sava's transaction compiler; it is not part of the published library, and Gradle does
not run Rust or access the network.

The oracle is `solana-message` 4.5.0's `Message::new_with_blockhash` and its locked
`solana-address`, `solana-instruction`, `solana-hash`, and `wincode` dependencies. Those
are the current crate versions in the local `anza-xyz/solana-sdk` checkout at the commit
recorded in the fixture. Most vectors are legacy; two zero-lookup v0 vectors pin the
shared transaction signature-count boundary. No address lookup semantics or transaction-v1
format is exercised.

The fixture also records the current Kit v7.0.0 release commit and the precise Kit source
functions independently reviewed for the same promotion, ordering, header, index, and
shortvec rules. Those TypeScript files were fetched read-only from the official
`anza-xyz/kit` repository at tag `v7.0.0` / commit
`58df993f4bea388121a872b33038c6af0ca3dd90` with `gh api`; Kit was not executed locally
and does not supply the fixture's bytes. Rust supplies the executable oracle, while the
Kit review is a separately recorded implementation cross-check without adding Node to
Gradle's test runtime.

Rust's message compiler and transaction wire reader intentionally expose an important
boundary distinction. Legacy and v0 headers can hold 128 required signatures and their
outer signature vector serializes the canonical two-byte ShortU16 value `80 01`, but the
current `VersionedTransaction` reader reserves a high first byte for transaction-version
discrimination and explicitly assumes legacy/v0 signature counts are below 128. The
generator executes both sides for both message formats: 127 round-trips, while 128 records
`rust_wire_round_trip=false`. Sava intentionally remains a permissive byte builder at this
boundary: it can emit the unsupported shape for analysis, while an RPC submission remains
responsible for rejecting the invalid transaction.

Within one signer/writable category, Rust orders keys by raw address bytes and Kit uses its
address comparator, while Sava's published public builder retains HashMap encounter order.
The Java test therefore compares public-builder semantics and uses Sava's existing
already-ordered-account overload for byte-for-byte Rust wire checks. It does not silently
change valid transaction IDs to imitate either reference's tie-break.

Regenerate or verify from this directory with:

```sh
NO_DNA=1 cargo run --locked --release -- --write
NO_DNA=1 cargo run --locked --release -- --check
```

`--check` compares generated bytes with the committed TSV. Dependency changes require a
deliberate lockfile update, fixture regeneration, and matching Java provenance updates.
